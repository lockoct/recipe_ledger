# git提交规则
1. 分批次提交，不要将所有变更都放到一次提交中，提交批次按照功能模块、前端/后端划分
2. 提交信息结构按照如下格式：
    ```
    标题 - 类型(模块): 变更描述
    空行
    正文 - 使用markdown无序列表列出变更详情
    ``` 
    示例：
    ```
    feat(permission): 前端权限模块优化
    
    - 新增 PermissionTreeNode 接口类型
    - 更新权限表单组件
    - 更新路由配置
    ```
3. 提交信息标题中，类型必须是以下之一：
    - feat：新增功能
    - fix：修复bug
    - docs：文档变更
    - style：代码格式变更（不影响代码逻辑）
    - refactor：代码重构（不新增功能，也不修复 bug）
    - perf：性能优化
    - test：测试相关
    - ci：持续集成相关配置文件或脚本的变更
    - chore：其他变更
4. 当一次提交无法划分到具体的模块时，标题可以省略模块
5. 如果标题能够直接描述清楚变更内容，可以不填写正文
6. 除了类型和模块，描述文字都使用中文编写
7. 未跟踪文件需要加入到跟踪列表中
8. 必须由用户确认了提交批次划分和提交信息，才能进行提交
